# RPA Process Generator

Пайплайн генерации процессов (.ltw) для платформы Primo RPA из текстового описания задачи.

## Схема работы

Текстовое ТЗ
|
v
Планировщик (Java) -- tool calling --> Сервис карточек
|
v
plan.json
|
v
OpenCode -- MCP --> Сервис карточек
|
v
Process.ltw


Планировщик разбивает ТЗ rpa-процесса на последовательность активностей, опираясь на реальный каталог, и выдает строгий JSON-план. AI-агент (напр., OpenCode) читает план, по каждому шагу получает полный XML-скелет активности из каталога и собирает итоговый .ltw файл.

## Структура

| Папка | Назначение |
|---|---|
| `agent_vibe_rpa_v1` | Планировщик на Java (Spring Boot). Принимает текстовое описание модуля, через цикл tool calling запрашивает активности у сервиса карточек и формирует `plan.json`. |
| `AVRPA_for_OpenCode` | Рабочая папка генератора. Содержит инструкции (`AGENTS.md`, `framework_rules.md`), MCP-прокси, примеры `.ltw` и генерируемые планы. |
| `RPA_Card_service` | Сервис карточек активностей (Python, FastAPI, Docker). Единый источник метаданных: параметры, описания и XML-скелеты активностей, разложенные по доменам. |

## Запуск

1. Сервис карточек: `docker-compose up` в папке `RPA_Card_service`.
2. Планировщик: стандартный запуск Spring Boot приложения в папке `agent_vibe_rpa_v1`.
3. Генератор: открыть папку `AVRPA_for_OpenCode` в OpenCode. Перед генерацией положить в папку `plan.json` от планировщика.

## Особенности

- Планировщик не выдумывает активности: используются только идентификаторы из каталога.
- Файлы `.ltw` сохраняются в кодировке UTF-16, как требует Primo RPA.
- Контейнерные активности (условия, циклы, обработка исключений) поддерживают вложенность и метки веток.
